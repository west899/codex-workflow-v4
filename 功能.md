# Codex Workflow V4 功能清单

> 只记录已经实现、随包交付、且有回归依据的能力。新任务默认 V4；V3 record 按原算法收尾。产品 V4，外环协议代次仍为 3。
>
> 总依据：`python3 -B verify_package.py`（macOS / CPython 3.9）。Windows / 3.12 / 3.13 未验证。
>
> 未实施：发布编排、merge-queue 产品集成、第二套 checkpoint 命令、自动 push/合并。integration/closeout 不写成 `released`。

## 1. 工作流基础与 V4 内环

| 能力 | 入口 | 依据 |
| --- | --- | --- |
| 安装到现有 Git 项目并保留治理文件 | `install.py` | `tests/test_install.py` |
| Coordinator / Developer / Reviewer / Integrator / Human 职责 | Skills、`protocol/AGENTS.md` | 安装后文件集；`verify_package.py` 检查 Skills/Hooks |
| task contract：范围、allowed paths、资源、验收、授权 | `task-record-v4` 模板 | `tests/test_v4_contract.py` |
| Evidence Contract v1：有限 scope、command-bound claim、fingerprint | `record-developer` / `record-review` | `tests/test_v4_workflow.py`, `tests/test_canonical_delivery.py` |
| `start` / `manual` / `stop` / `preflight` / `snapshot` / `gate` | `workflow_check.py` | `tests/test_workflow_check.py` |
| `completed` / `verified` / `done` / `released` 分称 | task/integration 字段 | `tests/test_v4_closeout.py`, `tests/test_v4_lifecycle.py` |
| 默认 dry-run，`--apply` 才写入 | 全部 state/lane 写命令 | `tests/test_workflow_state.py` |
| 新任务默认 v4：`delivery_contract` + `decision_log`、focus、观察配方、架构基线 | `layout.json` `default_new_task_version=4` | `tests/test_v4_contract.py`, `tests/test_v4_lifecycle.py` |
| `request-decision` / `record-decision`；required checkpoint 未确认不能独立 Review | `workflow_state.py` | `tests/test_v4_workflow.py` |
| STATUS / Stop Hook 派生产品摘要，不批准、不集成 | `workflow_check.py status`, `codex_stop_hook.py` | `tests/test_v4_status.py`, `tests/test_stop_hook.py` |
| Backlog focus/WIP；supporting 绑定同一 focus | Backlog metadata | `tests/test_v4_phase_b.py` |
| 滚动 Requirements：future Must 不能进入已批准合同 | `rolling-promotion`, impact | `tests/test_v4_phase_b.py` |
| small/no-trigger 可 `retrospective.not_required`；高风险底线不被 core_slice 降低 | planning/risk gate | `tests/test_v4_phase_b.py` |
| 护栏 fitness 不信任自报；冲突决定必须 supersede | registry / decision | `tests/test_v4_phase_b.py` |
| pending/queued 仅 abandon-only | `pending-queued-recovery` | `tests/test_v4_phase_b.py` |

## 8. 远端协作与 provider receipt

| 能力 | 入口 | 依据 |
| --- | --- | --- |
| remote_pr_ci strict-ff：`result == pr_head`，CI `success` | `prepare-remote-closeout` | `tests/test_v4_phase_c.py`, `tests/test_end_to_end.py` |
| `skipped`/`neutral`、非 ff、`head != result` fail closed | 同上 | `tests/test_v4_phase_c.py` |
| 只读 `provider-receipt-v1`；不能替代 Reviewer 或 ff/CI | `workflow_check.py provider-receipt` | `tests/test_v4_phase_c.py` |
| receipt 绑定 delivery/snapshot；admin bypass / stale review 失败 | `prepare-remote-closeout` | `tests/test_v4_phase_c.py` |
| closeout 要求 `review.status == pass` | `prepare-remote-closeout` | `tests/test_v4_phase_c.py` |
| remote_preassigned / remote_claimed / takeover / handoff / release | `workflow_lane.py remote-*` | `tests/test_remote_claim_recovery.py`, `tests/test_remote_release.py`, `tests/test_end_to_end.py` |
